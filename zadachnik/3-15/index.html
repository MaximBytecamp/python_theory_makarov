§1Разборы: как решать и оформлять

Три задачи решены полностью. В них встречаются сумма списка, начальное значение, подсчёт по условию и склейка списков через sum().

Разбор 1

Выручка и средняя за день

★☆☆базовая

Магазин записывает выручку по дням. Вводятся количество дней и выручка за каждый день. Если дней нет, выведите Данных нет. Иначе выведите общую выручку и среднюю за день с двумя знаками после запятой.

Как рассуждаем

  1. Все значения сначала складываем в список, потом одним вызовом sum(sales) получаем общую выручку.
  2. Средняя за день — сумма, делённая на количество дней. Если дней нет, делить нельзя: сам sum() на пустом списке даст 0, а вот деление на ноль упадёт с ошибкой.
  3. Поэтому случай «дней нет» отделяем условием, а общую сумму и среднюю выводим только в ветке else.

Проверка на других данных

Пример 1
Ввод
3
10
20
25
Вывод
Всего: 55
В среднем за день: 18.33
Пример 2
Ввод
0
Вывод
Данных нет
Сумма пустого списка равна 0

sum([]) возвращает 0. Ошибка появляется позже, на делении: 0 / 0 недопустимо. Сумму можно считать без проверки, а делить на количество — только когда оно не равно нулю.

Разбор 2

Касса с начальным остатком

★★☆средняя

В начале смены в кассе лежит какая-то сумма. Вводятся остаток на начало смены, количество продаж и сумма каждой продажи. Выведите, сколько денег в кассе в конце смены (В кассе: …), и сколько продаж было на 1000 рублей и больше (Крупных продаж: …).

Как рассуждаем

  1. Деньги в кассе — это остаток плюс все продажи. Второй аргумент sum() — начальное значение: sum(sales, opening) стартует не с нуля, а с остатка.
  2. Крупные продажи считаем без отдельного счётчика. На каждой продаже добавляем в список True или False для условия «от 1000».
  3. True при сложении равно 1, False равно 0. Поэтому sum(is_large) — это число продаж, для которых условие выполнилось.

Проверка на других данных

Пример 1
Ввод
1000
0
Вывод
В кассе: 1000
Крупных продаж: 0
Пример 2
Ввод
0
2
999
1000
Вывод
В кассе: 1999
Крупных продаж: 1
Начальное значение — не вторая коллекция

Второй аргумент sum() прибавляется к результату один раз в самом начале. Для чисел это обычно 0 и его не пишут. Список для сложения всегда первый: запись sum(opening, sales) с перепутанным порядком выдаст ошибку.

Разбор 3

Заказы всех курьеров

★★★повышенная

У службы доставки несколько курьеров. Вводится количество курьеров, затем для каждого — количество его заказов и сумма каждого заказа. Выведите, сколько заказов всего, их общую сумму и в третьей строке все суммы в порядке ввода: Все суммы: 300 450 120.

Как рассуждаем

  1. Заказы каждого курьера собираем в отдельный список, а эти списки — в один общий список списков.
  2. Нужен один плоский список всех заказов. Сложение списков + склеивает их, а sum() складывает всё подряд, поэтому sum(all_lists, []) склеит все курьерские списки.
  3. Начальное значение здесь обязательно пустой список. Без него sum() начнёт с числа 0 и попытается сложить число со списком.
  4. Дальше работаем с плоским списком теми же средствами: len(), sum(), print(*merged).

Без [] сложение списков не работает

sum([[1, 2], [3]]) заканчивается ошибкой TypeError: сначала к 0 пытаются прибавить список. Запись sum([[1, 2], [3]], []) даёт [1, 2, 3].

§3Как проверить своё решение

  1. Запустите программу и введите значения из колонки «Ввод» — каждое значение отдельной строкой, после каждого Enter.
  2. Сравните то, что напечатала программа, с колонкой «Вывод» — символ в символ: пробелы, двоеточия, количество знаков после точки.
  3. Подсказки input() в примерах не показаны: текст подсказки у каждого свой, проверяется только результат.
  4. Прогоните все примеры, а не только первый: второй обычно ловит ошибку, которую первый пропускает.
Оформление, которое проверяют

Имена переменных называют смысл: total_cost, а не x. Данные — вверху, расчёт — отдельными строками, вывод — в конце. Одно и то же выражение не повторяется: результат сохраняется в переменную и дальше используется по имени.
