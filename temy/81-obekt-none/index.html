6.13

Объект None:
отсутствие значения

В Python «ничего» — это тоже объект. None обозначает отсутствие значения: его возвращает функция без return, им отмечают ещё не заполненную переменную и им сообщают, что результата не нашлось.

«Разбираться в основах — значит экономить время в будущем.»

§1Что означает None

None — специальное значение, которое означает «ничего» или «значения нет». Это не ноль, не пустая строка и не False: те говорят «значение есть, и оно пустое», а None говорит «значения не существует».

Разница важная. Ноль градусов — это измеренная температура. None в поле температуры — датчик не ответил. Оба «пустые» на вид, но означают разное, и путать их нельзя.

§2Тип NoneType и единственный объект

None — экземпляр класса NoneType, и это единственный объект такого типа во всей программе.

Такой объект в единственном экземпляре называют синглтоном. Сколько бы имён на него ни ссылалось, в памяти он один — и именно поэтому его проверяют оператором is, а не сравнением.

§3Функция без return

Функция, которая ничего не возвращает явно, всё равно возвращает значение — None.

То же самое верно для return без значения. И для встроенных функций: print() печатает текст, но возвращает None — поэтому x = print("текст") кладёт в x вовсе не строку.

§4Проверка через is

Правильный способ проверить, что значение отсутствует, — оператор is.

== спрашивает «равны ли значения», а is — «это один и тот же объект». Поскольку None существует в единственном экземпляре, вопрос об идентичности здесь и точнее, и быстрее: он не зависит от того, как чужой класс определил своё сравнение. Проверка отсутствия пишется как is None, наличия — как is not None.

§5None в логическом контексте

None относится к ложным значениям — тем самым, о которых шла речь в главе 3.16.

§6Почему if value недостаточно

Раз None ложно, кажется соблазнительным писать просто if value:. Но ложны и ноль, и пустая строка, и пустой список.

Ноль градусов — реальное измерение, а не отсутствие данных. Когда нужно отличить «нет значения» от «значение пустое», проверка обязана быть именно is None.

§7None как значение по умолчанию

Частая роль None — умолчание для необязательного аргумента, о которых шла речь в главе 6.5.

Такое умолчание честнее любого другого: оно не притворяется осмысленным значением, а прямо сообщает, что параметр не задавали.

§8Ловушка изменяемого умолчания

У None в этой роли есть ещё одна причина. Значение по умолчанию вычисляется один раз — при объявлении функции, а не при каждом вызове. Для списка это оборачивается сюрпризом.

Все вызовы используют один и тот же список, и он растёт от вызова к вызову. Лечение — умолчание None и создание нового объекта внутри функции.

Правило простое: изменяемый объект (список, словарь, множество) никогда не ставят значением по умолчанию. Ставят None, а сам объект создают в теле функции.

§9None как «результата нет»

Функция поиска возвращает None, когда искать было нечего.

Так же поступает встроенный метод словарей: d.get("ключ") возвращает None вместо исключения, если ключа нет. Обратите внимание, почему здесь нельзя проверять через if not result: индекс 0 — законный результат, а он тоже ложен.

§10Заглушка для будущего значения

Имя иногда нужно создать заранее, хотя настоящее значение появится позже и не при всех условиях.

Без первой строки ветка else оставила бы имя несуществующим, и обращение к нему вызвало бы NameError. None здесь означает «сюда ещё ничего не записали».

§11None внутри коллекции

В списке или словаре None отмечает пропущенный элемент, не сбивая длину и нумерацию.

Если бы пропуск просто выбросили, четвёртое измерение сдвинулось бы на третью позицию, и связь с моментом времени потерялась. None сохраняет структуру данных.

§12Типичная авария: AttributeError

Главная ошибка при работе с None — забыть проверить результат и сразу его использовать.

Это одно из самых частых сообщений в Python, и читать его нужно так: «где-то выше функция вернула None, а я обращаюсь с ним как со строкой». Лечится проверкой перед использованием.

§13None и аннотации типов

В аннотациях из главы 6.11 возможность отсутствия записывают явно.

Запись int | None — сигнал тому, кто вызывает функцию: результат придётся проверить. Функция, которая ничего не возвращает, аннотируется как -> None.

§15Проверьте себя

Чем None отличается от 0 и пустой строки?

None означает, что значения нет вовсе. Ноль и пустая строка — существующие значения, просто «пустые» по содержанию.

Что вернёт функция, в которой нет return?

None. То же самое вернёт return без значения.

Почему проверяют is None, а не == None?

None существует в единственном экземпляре, поэтому корректнее спрашивать об идентичности объекта. Такая проверка быстрее и не зависит от того, как чужой класс определил сравнение.

Чем плохо def f(lst=[])?

Значение по умолчанию создаётся один раз при объявлении функции, поэтому все вызовы работают с одним списком и он накапливает изменения.

О чём говорит AttributeError: 'NoneType' object has no attribute ...?

Что переменная содержит None, хотя ожидался объект с методами: скорее всего, выше функция не нашла результат и вернула None.

Итог главы

None — единственный объект типа NoneType, обозначающий отсутствие значения. Его возвращает функция без return, им отмечают необязательные аргументы, пропуски в данных и отрицательный результат поиска. Проверять его нужно оператором is, а не общей проверкой на истинность: иначе ноль и пустая строка будут приняты за отсутствие данных. И главное практическое правило главы: изменяемый объект не ставят значением по умолчанию — там всегда стоит None.
