§1Три границы

Три метода этой главы работают в трёх разных местах строки, и это единственное, что нужно запомнить о них сразу.

Все три возвращают новый результат и не меняют исходную строку — строки неизменяемы.

§2join(): сборка строки

join() собирает одну строку из набора частей, вставляя разделитель между ними.

Разделитель вставляется между элементами, а не после каждого: для трёх слов его копий будет две. По краям строки его нет.

§3Почему метод у разделителя

Запись " ".join(words) поначалу выглядит вывернутой наизнанку: логичнее ждать words.join(" "). Причина в том, что join() — метод строки, а соединять он умеет любую коллекцию.

Будь join() методом списка, его пришлось бы отдельно определять для кортежа, множества и всего остального. Третья строка показывает побочный эффект: строка тоже коллекция, и она разберётся на символы.

§4Только строки

Все элементы должны быть строками. Числа join() сам не преобразует.

Числа переводят в строки заранее — включением из главы 4.10 или функцией map() из главы 6.8.

§5Пустой разделитель

Разделитель может быть пустым — тогда части просто склеиваются.

Эта форма уже встречалась в главе 5.1, когда список кодов превращали обратно в текст.

§6join() вместо склейки в цикле

Ту же строку можно собрать сложением в цикле. Результат совпадёт, но способ хуже.

Причина в неизменяемости: result += part не дописывает символы, а строит новую строку из старой и добавки. Для сотни частей это сто промежуточных строк. join() сначала считает итоговую длину, затем заполняет результат один раз.

§7strip(): очистка краёв

Без аргументов strip() удаляет пробельные символы с обоих краёв — все те, что проверяет isspace() из главы 5.8.

Пробел между словами остался: метод работает только по краям и внутрь не заглядывает. Это первое, что нужно делать с текстом из input() или из файла.

§8lstrip() и rstrip()

Если чистить нужно только одну сторону, есть отдельные методы.

Буквы в названиях — от left и right, та же логика, что у rfind() из главы 5.5.

§9Аргумент — это набор символов

Методу можно передать строку с символами, которые нужно удалять. И вот здесь начинается главное недоразумение темы: аргумент — не подстрока, а набор символов.

Метод движется с каждого края внутрь и удаляет символы, пока они входят в набор. Порядок символов в аргументе не имеет значения: "Py!", "!yP" и "y!P" сработают одинаково.

§10Ловушка strip(".csv")

Самое частое применение этого недоразумения — попытка убрать расширение файла.

Код проходит проверку, попадает в проект и ломается на первом же файле, чьё имя начинается или заканчивается «неудачными» буквами.

Почему это опасно

Набор ".csv" — это символы ., c, s, v. С левого края у mycsv.csv они не встретились сразу (m не в наборе), зато с правого метод съел .csv, затем v, s, c из самого имени и остановился только на y. Ошибка не проявляется на удобных примерах — и потому доживает до продакшена.

§11removeprefix() и removesuffix()

Для удаления именно подстроки существуют отдельные методы. Они появились в Python 3.9 ровно из-за ловушки выше.

Вызов для "mycsv.csv"РезультатЧто делает
strip(".csv")"my"удаляет символы набора с краёв
removesuffix(".csv")"mycsv"удаляет подстроку с конца, один раз

Если подстроки нет, removesuffix() просто возвращает строку без изменений — ошибки не будет. Правило простое: убираете символы — strip(), убираете слово — removeprefix() или removesuffix().

§12partition(): три части

partition() делит строку по первому вхождению разделителя и возвращает кортеж ровно из трёх строк: до, сам разделитель, после.

Это готовая замена приёму с find() из главы 5.5: не нужно ни считать индексы, ни прибавлять единицу. Важно, что делится строка только по первому вхождению.

Для разбора настроек это именно то, что нужно: ключ отделён, а значение осталось целым.

§13Разделителя нет

Даже когда разделитель не найден, результат остаётся тройкой — меняется лишь её наполнение.

Постоянная длина результата — главное достоинство метода: распаковка в три переменные не сломается никогда. Проверять наличие разделителя удобно по средней части — если она пуста, разделителя не было.

§14rpartition()

Как и у find(), есть версия, ищущая с конца.

Для пути к файлу нужен именно rpartition(): он отделяет имя файла от каталогов.

§15partition() или split()

Разделять строку умеет и split() из главы 5.10. Выбирают по тому, сколько частей ожидается.

partition(sep)split(sep)

Правило: делите надвое по первому разделителю — partition(), потому что распаковка предсказуема. Делите на все части — split().

§17Проверьте себя

Почему join() вызывается у разделителя, а не у списка?

Это метод строки, и он умеет соединять любую коллекцию — список, кортеж, множество. Иначе его пришлось бы определять для каждого типа отдельно.

Удалит ли strip("ab") подстроку "ab"?

Нет. Аргумент — набор символов: с краёв удаляются любые идущие подряд a и b в любом порядке.

Что вернёт "mycsv.csv".strip(".csv")?

"my". С правого края съедены .csv, а затем v, s, c из самого имени. Нужен removesuffix().

Сколько элементов возвращает partition()?

Всегда три, даже если разделитель не найден — тогда две части пусты.

Как отделить имя файла от пути?

rpartition("/"): он делит по последнему разделителю.

Чем partition() лучше split() для разбора ключ=значение?

Результат всегда из трёх частей, поэтому распаковка не сломается, а знак = внутри значения не разорвёт строку лишний раз.

Итог главы

join() вызывается у разделителя и требует, чтобы все части были строками, — так он умеет собирать любую коллекцию и делает это за один проход, в отличие от склейки в цикле. strip() удаляет с краёв набор символов, а не подстроку: для удаления слова есть removeprefix() и removesuffix(). partition() делит по первому вхождению и всегда возвращает три части, поэтому распаковка его результата безопасна.
