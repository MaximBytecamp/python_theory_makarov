§1Новый набор или изменение

Каждая операция главы 4.7 существует в двух видах. Один строит новый набор, другой меняет левый операнд.

ОперацияНовый результатИзменение слева
объединениеa.union(b), a | ba.update(b), a |= b
разностьa.difference(b), a - ba.difference_update(b), a -= b
пересечениеa.intersection(b), a & ba.intersection_update(b), a &= b
симметрическая разностьa.symmetric_difference(b), a ^ ba.symmetric_difference_update(b), a ^= b

Различить их легко по названию: суффикс _update и знак = у оператора означают «изменить на месте». Это та же пара, что sort() и sorted() в главе 3.11.

§2update(): добавить всё

Метод добавляет в множество все элементы аргумента. Повторы отсеиваются сами.

Метод уже встречался в главе 4.6 — он относится к add() так же, как extend() к append(). Здесь важно другое: update() и есть изменяющая версия объединения.

§3Оператор |=

Короткая запись того же действия.

Запись a |= b читается как a += b у чисел: «взять текущее значение, применить операцию, положить обратно».

§4difference_update(): убрать

Метод удаляет из множества всё, что встретилось в аргументе.

Отсутствующие элементы ошибки не вызывают — метод ведёт себя как discard() из главы 4.6, только сразу для группы. Это удобно: не нужно проверять, что там есть на самом деле.

§5intersection_update(): оставить общее

Обратная задача: оставить только то, что есть и в аргументе.

Типичное применение — фильтрация: «оставить из запрошенного только разрешённое». Оператор &= делает то же самое короче.

§6symmetric_difference_update()

Метод оставляет то, что было ровно в одном из наборов, — получается переключение принадлежности.

Общий элемент sql удалился, а docker добавился. Именно так работают переключатели в интерфейсах: повторный клик по выбранному тегу его снимает.

§8Методы принимают списки

Различие между методом и оператором здесь то же, что в главе 4.7.

А values.update([2]) отработает без нареканий. Отсюда практический вывод: с данными из внешнего источника, которые обычно приходят списком, удобнее методы.

§9Несколько аргументов

Три метода из четырёх принимают сразу несколько коллекций.

МетодНесколько аргументов
update()да
difference_update()да
intersection_update()да
symmetric_difference_update()нет, ровно один

Исключение объяснимо: симметрическая разность для трёх наборов сразу не имеет однозначного смысла. Попытка передать два аргумента даёт TypeError: takes exactly one argument.

§10Все возвращают None

Правило из главы 3.10 действует и здесь: метод, меняющий коллекцию, возвращает None. Запись values = values.update([3]) уничтожила бы множество.

§11Почему это важно: два имени

Пока у множества одно имя, выбор между a = a | b и a |= b ни на что не влияет. Разница проявляется, когда имён два, — как в главе 3.10.

Две почти одинаковые строки

a |= b меняет сам объект — изменение видят все имена. a = a | b создаёт новое множество и связывает с ним только a; прежний объект остаётся у остальных имён. Если множество передавали в функцию или сохраняли под другим именем, разница становится решающей.

Последняя строка — про эффективность: result = result | new в цикле создаёт новое множество на каждом шаге, как склейка строк в главе 5.9.

§13Практика: фильтрация набора

Типичный сценарий: собрать запрошенное, убрать запрещённое, оставить доступное.

Каждый шаг меняет один и тот же набор, промежуточные копии не создаются. Если бы понадобилось сохранить исходный запрос, первую строку заменили бы на result = requested | set(extra).

§15Проверьте себя

Чем a |= b отличается от a = a | b?

Первое меняет сам объект, и изменение видят все его имена. Второе создаёт новое множество и связывает с ним только a.

Что возвращают методы с суффиксом _update?

None. Они меняют множество на месте, поэтому присваивать их результат нельзя.

Почему values |= [2] не работает?

Оператор требует множество с обеих сторон. Метод update() принимает любую итерируемую коллекцию.

Меняется ли правый набор при a -= b?

Нет. Все изменяющие операции односторонние: меняется только левый набор.

Какой метод не принимает нескольких аргументов?

symmetric_difference_update() — для трёх наборов сразу эта операция не имеет однозначного смысла.

Что удобнее для накопления результата в цикле?

result.update(...): операция result = result | new создавала бы новое множество на каждом шаге.

Итог главы

У каждой операции множеств есть версия с суффиксом _update и оператор со знаком = — они меняют левый набор на месте и возвращают None. Правый набор при этом не меняется никогда. Выбор между a |= b и a = a | b становится существенным, когда у множества несколько имён: первое изменение увидят все, второе — только переменная слева. Методы принимают любые коллекции, операторы — только множества.
