frozenset
в Python

Неизменяемый вариант множества. Отношение frozenset к set ровно такое же, как кортежа к списку: те же возможности чтения, никаких изменений — и, как следствие, хешируемость. Только благодаря ей набор может стать ключом словаря или элементом другого множества.

§1Зачем нужен ещё один тип

Глава 4.5 закончилась ограничением: множество нельзя положить внутрь другого множества и нельзя сделать ключом словаря. Причина известна из главы 4.1 — set изменяем, а значит не хешируем.

frozenset закрывает именно этот пробел. Он делает для множества то же, что кортеж делает для списка: убирает изменяемость и тем самым возвращает хешируемость.

§3Создание

Своего литерала у типа нет — только функция-конструктор, принимающая любую итерируемую коллекцию.

Повторы отсеиваются так же, как у set: из двух "read" остался один, а из пяти букв слова hello — четыре.

§4Чтение работает так же

Индексов по-прежнему нет: roles[0] даёт TypeError: 'frozenset' object is not subscriptable. Порядок обхода так же не определён, поэтому для воспроизводимого вывода нужен sorted().

§5Методов изменения нет

Здесь AttributeError, а не TypeError: метод не запрещён — его просто не существует. Так же отсутствуют remove(), discard(), pop(), clear() и все методы с суффиксом _update из главы 4.8.

§6Операции создают новый набор

Операции из главы 4.7 доступны полностью — они и раньше не меняли исходные наборы.

Недоступны только изменяющие версии: base |= {"delete"} вызовет ошибку, потому что это сокращение от base.update(...).

§7Тип результата

set и frozenset свободно смешиваются в операциях. Тип результата определяет левый операнд.

Деталь незаметная, но важная: если результат должен остаться неизменяемым, слева должен стоять frozenset. Иначе получится обычный set, и его снова нельзя будет использовать как ключ.

§8Отношения множеств

Это делает frozenset удобным для наборов прав и ролей: состав зафиксирован типом, а все проверки достаточности остаются доступными.

§9Сравнение с set

Равенство определяется составом, а не типом.

Порядок при создании тоже роли не играет: {1, 2} и {2, 1} — один и тот же набор. Это отличает frozenset от кортежа, где порядок значим, — сравнение будет в §12.

§10Ключ словаря

Главное применение типа. Ключом становится сам набор целиком, и порядок перечисления его не меняет.

Обратите внимание: искали {"write", "read"}, а в словаре лежит {"read", "write"}. Для frozenset это одно и то же значение с одним и тем же хешем.

§11Элемент множества

Второе применение — множество множеств, невозможное с обычным set.

Уникальность работает и здесь: два первых набора равны по составу, поэтому в множестве остался один. Так удобно собирать, например, уникальные комбинации тегов или сочетания участников.

§12frozenset или tuple

Оба типа неизменяемы и хешируемы, поэтому оба годятся в ключи. Выбор определяется тем, важен ли порядок и допустимы ли повторы.

НужноТип
порядок значим (координаты, дата)tuple
повторы значимыtuple
набор без порядка (права, теги)frozenset
операции пересечения и разностиfrozenset

Практическое правило: если ключ — это запись из полей, берите кортеж; если набор из элементов, берите frozenset.

§13Практика: кеш по набору

Задача, где frozenset незаменим: запомнить результат вычисления для набора параметров, не зависящего от порядка.

С кортежем пришлось бы заранее сортировать элементы, чтобы ("a", "b") и ("b", "a") совпали. frozenset решает это сам.

§14Когда он действительно нужен

В повседневном коде frozenset встречается нечасто. Ситуаций, где он оправдан, всего несколько.

СитуацияПочему frozenset
набор как ключ словаряset не хешируется
множество множествто же ограничение
константа с набором значенийтип запрещает случайную правку

§16Проверьте себя

Зачем нужен frozenset, если есть set?

Обычное множество изменяемо и потому не хешируется: его нельзя сделать ключом словаря или элементом другого множества. frozenset снимает это ограничение.

Почему roles.add(x) даёт AttributeError, а не TypeError?

Метод не запрещён — его просто не существует у типа, как append() у кортежа.

Какого типа будет результат {1} | frozenset({2})?

set: тип наследуется от левого операнда. Чтобы получить frozenset, он должен стоять слева.

Равны ли {1, 2} и frozenset({2, 1})?

Да. Равенство определяется составом, а не типом и не порядком перечисления.

Когда лучше кортеж, а когда frozenset?

Кортеж — если порядок или повторы значимы, то есть ключ представляет собой запись из полей. frozenset — если ключ это набор, где порядок не важен.

Можно ли создать frozenset литералом?

Нет, своего литерала у типа нет — только конструктор frozenset(...).

Итог главы

frozenset относится к set так же, как кортеж к списку: те же чтение, перебор и операции, но без единого метода изменения — и потому хешируемый. Это открывает два применения, недоступные обычному множеству: набор как ключ словаря и множество множеств. При смешивании типов результат наследует тип левого операнда, а равенство определяется составом, а не типом и не порядком. Выбирая между frozenset и кортежем, ориентируйтесь на смысл: набор без порядка или запись из полей.
