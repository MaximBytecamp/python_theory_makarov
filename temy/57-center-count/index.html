center()
и count()

§1Две задачи в одной главе

Методы center() и count() связаны только соседством в справочнике: первый оформляет текст, второй его исследует. Общего у них два свойства, важных для всех строковых методов.

  1. Ни один не меняет исходную строку — строки неизменяемы, возвращается новый результат.
  2. Оба принимают дополнительные параметры со значениями по умолчанию, и именно в этих параметрах прячутся неожиданности.

§2center(): дополнение до ширины

center(width, fillchar=" ") возвращает строку длиной width, в середине которой стоит исходный текст. Свободное место заполняется — по умолчанию пробелами.

Вертикальные черты добавлены только для наглядности: без них пробелы по краям не видно. Ширина 12 относится к результату целиком, а не к добавленному заполнению.

§3Куда идёт лишний символ

Если свободных позиций нечётное число, разделить их поровну нельзя. Python отдаёт лишний символ правой стороне.

В первом случае свободных позиций пять: две слева и три справа. Во втором их четыре, и они делятся поровну. Значит, точной симметрии от center() ждать нельзя — она получается только при совпадении чётности ширины и длины текста.

§4Символ заполнения

Второй параметр задаёт, чем заполнять свободное место. Он не обязателен, по умолчанию — пробел.

Это типичное применение метода: заголовки секций в текстовом выводе, разделители в логах, простые «рамки» в консольных программах.

§5Ровно один символ

fillchar должен состоять ровно из одного символа. Ни пустая строка, ни две буквы не подойдут.

Ограничение не произвольное: метод дополняет строку до точной ширины, а из двухсимвольных блоков произвольную ширину не собрать.

§6Малая ширина не обрезает

Если width меньше длины строки, дополнять нечего — метод возвращает исходный текст целиком.

center() не гарантирует ширину

Легко решить, что text.center(10) всегда даёт ровно десять символов, и построить на этом выравнивание таблицы. Для длинного текста результат окажется шире, и колонки поедут. Если ширина обязательна, длину нужно ограничивать срезом: text[:10].center(10).

§7ljust() и rjust()

У center() есть два родственных метода с той же сигнатурой, но другим прижатием текста.

МетодГде текстТипичное применение
ljust(width)прижат влевоназвания, левая колонка таблицы
rjust(width)прижат вправочисла, суммы, правая колонка
center(width)по серединезаголовки и разделители

Для чисел с ведущими нулями есть отдельный метод zfill() — он разбирается в главе 5.10.

§8Практика: ровные колонки

Вместе эти методы дают простой способ вывести таблицу без внешних библиотек: названия прижимаем влево, числа — вправо.

Числа приходится переводить в строку через str(): методы выравнивания принадлежат строкам, у чисел их нет.

§9count(): подсчёт вхождений

count(substring) возвращает, сколько раз подстрока встречается в строке. Если не встречается — 0, а не ошибка.

Искать можно и один символ — это просто подстрока длиной один.

§10Границы start и end

Полная форма — count(substring, start, end). Дополнительные параметры ограничивают область поиска, работая ровно как границы среза: start включается, end — нет.

Третья строка показывает, что именно просматривается. Обратите внимание: первое red обрезано до ed и потому не считается, а вот red на границе end уместилось целиком. Запись text.count(part, start, end) равнозначна text[start:end].count(part), но не создаёт промежуточную строку.

§11Непересекающиеся вхождения

Метод считает только те совпадения, которые не накладываются друг на друга. Найдя вхождение, он продолжает поиск за его концом, а не со следующего символа.

Для перекрывающихся совпадений count() не подходит — их считают циклом с find() из главы 5.5, сдвигая позицию на один символ.

§12count() учитывает регистр

Совпадение проверяется посимвольно, поэтому Python и python — разные подстроки.

Как и в главе 5.2, нормализовать нужно обе стороны: и строку, и искомую подстроку.

§13Пустая подстрока

Пустая строка считается подстрокой, которая находится в каждом промежутке между символами, а также перед первым и после последнего.

Результат всегда равен len(text) + 1. Практической пользы в этом нет, но знать стоит: если подстрока приходит из переменной и та случайно оказалась пустой, счётчик покажет неожиданно большое число вместо нуля.

§14count() или in

Если нужно только выяснить, есть ли подстрока, count() — избыточный инструмент: он дочитывает строку до конца, даже когда ответ уже известен.

ЗадачаЗаписьЧто делает
есть ли вообщеpart in textостанавливается на первом совпадении
сколько разtext.count(part)проходит строку целиком

Запись if text.count(part) > 0 работает верно, но if part in text и короче, и быстрее. Для длинного текста разница становится заметной: count() всегда просматривает всю строку.

§16Проверьте себя

Что произойдёт, если width меньше длины строки?

center() вернёт исходную строку целиком, без обрезки. Гарантии ширины метод не даёт.

Куда попадёт лишний символ заполнения?

Вправо. При нечётном числе свободных позиций справа окажется на один символ больше.

Чем ljust() отличается от rjust()?

Прижатием текста: ljust() оставляет его слева и дополняет справа, rjust() — наоборот.

Считает ли count() перекрывающиеся вхождения?

Нет. После совпадения поиск продолжается за его концом, поэтому "aaa".count("aa") равно 1.

Почему "abc".count("") равно 4?

Пустая строка находится на каждой границе: перед первым символом, между символами и после последнего. Всегда len(text) + 1.

Когда вместо count() лучше in?

Когда нужен только факт наличия. in останавливается на первом совпадении, а count() дочитывает строку до конца.

Итог главы

center() дополняет короткую строку до указанной ширины одним символом заполнения, отдавая лишнюю позицию правой стороне; ширину он при этом не гарантирует — длинный текст возвращается целиком. Вместе с ljust() и rjust() он позволяет верстать ровные колонки. count() считает непересекающиеся вхождения с учётом регистра и может ограничить поиск границами start и end, которые читаются как границы среза.
