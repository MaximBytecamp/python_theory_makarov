§1Зачем нужно множество

Две задачи встречаются постоянно: «убрать повторы» и «проверить, встречалось ли это раньше». Списком обе решаются, но плохо.

Множество — это, по сути, словарь без значений: та же хеш-таблица из главы 4.2, только хранятся одни ключи. Отсюда и оба его свойства: элементы уникальны, потому что ключи уникальны, и поиск мгновенный, потому что идёт по хешу.

§2Что хранит set

Множество (set) — изменяемая коллекция уникальных хешируемых элементов без порядка и индексов.

§4Повторы исчезают

Добавление уже существующего элемента не создаёт второй экземпляр и не вызывает ошибку — операция просто ничего не делает. Это отличает add() от append() у списка.

§5Пустое множество

Фигурные скобки заняты словарём, поэтому пустое множество создают только функцией.

Причина историческая: словарь появился в языке раньше и занял литерал {}. Ошибка коварна тем, что не проявляется сразу — {}.add(x) упадёт лишь на первой попытке добавить элемент.

§6Индексов нет

Это не недоработка, а следствие устройства: элементы лежат в хеш-таблице по своим хешам, и «первого» среди них не существует. Нужен порядок — берите список.

§7Порядок не гарантирован

При выводе множество показывает элементы в каком-то порядке, и его легко принять за осмысленный. Полагаться на него нельзя: он зависит от хешей и истории добавлений, а для строк может меняться от запуска к запуску.

Ошибка, которая проходит тесты

Если код опирается на порядок вывода множества, он может работать месяцами и сломаться при первом же изменении данных. Для воспроизводимого вывода всегда используйте sorted(values).

В отличие от словаря, который с Python 3.7 сохраняет порядок добавления, множество такой гарантии не даёт вовсе.

§10Насколько это быстрее

Разница между in для списка и для множества не косметическая. В списке Python сравнивает элементы по очереди, в множестве — сразу вычисляет, где значение должно лежать.

Разница здесь — четыре порядка, и она растёт вместе с размером данных.

§12Равные значения разных типов

Уникальность определяется равенством, а не типом. Значения, равные друг другу, считаются одним элементом.

В Python 1 == 1.0 == True, а значит для множества это одно и то же значение. Остаётся тот экземпляр, который добавили первым. То же правило действует для ключей словаря, и на практике оно всплывает при смешивании целых и дробных чисел или bool с числами.

§14Уникальность с порядком

Когда порядок первого появления нужно сохранить, используют не множество, а словарь: его ключи тоже уникальны, но порядок добавления сохраняется.

dict.fromkeys() из главы 4.3 создаёт словарь, где ключи — элементы списка, а значения не нужны. Приём стоит запомнить: он решает задачу, которую множество решить не может.

§15Практика: уже обработанные

Второе классическое применение — запоминать, что уже встречалось.

Множество здесь делает сразу два дела: хранит уникальные идентификаторы и мгновенно отвечает, встречался ли каждый следующий. Со списком проверка in замедлялась бы по мере роста данных.

§18Проверьте себя

Чем пустое множество отличается по записи от пустого словаря?

Множество создают только как set(): литерал {} всегда даёт словарь.

Почему у множества нет индексов?

Элементы лежат в хеш-таблице по своим хешам, а не по позициям, поэтому понятий «первый» и «второй» не существует.

Почему проверка in в множестве быстрее, чем в списке?

В списке элементы сравниваются по очереди, а в множестве Python по хешу сразу вычисляет, где значение должно лежать.

Сколько элементов будет в {1, 1.0, True}?

Один. Все три значения равны между собой, а уникальность определяется равенством, а не типом.

Как убрать повторы, сохранив порядок?

list(dict.fromkeys(items)): ключи словаря уникальны и сохраняют порядок добавления.

Когда список подходит лучше множества?

Когда важен порядок, нужен доступ по индексу или повторы несут смысл.

Итог главы

Множество — это словарь без значений: та же хеш-таблица, поэтому элементы уникальны, а проверка принадлежности не зависит от размера коллекции. У множества нет индексов и нет гарантированного порядка, и для воспроизводимого вывода нужен sorted(). Элементы должны быть хешируемыми, а равные значения разных типов считаются одним элементом. Если вместе с уникальностью нужен порядок первого появления, множество не подходит — подходит dict.fromkeys().
