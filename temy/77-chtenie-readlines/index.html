Чтение:
readlines()

Метод возвращает список всех строк файла — каждую вместе с завершающим переводом строки. Это удобно, когда нужен именно список: с индексами, сортировкой и повторными проходами. Плата — весь файл оказывается в памяти.

§1Список строк

readlines() читает файл до конца и возвращает список, в котором каждый элемент — одна строка.

Дальше это самый обычный список: доступен по индексу, поддерживает срезы, сортировку и всё остальное из модуля 3.

§2Переводы строк сохраняются

Как и readline(), метод оставляет \n в конце каждого элемента. Это регулярно портит сравнения.

§3Убрать переводы

Есть два способа получить список без \n, и второй короче.

Разница есть в деталях: strip() из главы 5.9 убирает и пробелы по краям, а splitlines() из главы 5.10 — только переводы строк. Если ведущие пробелы значимы, подходит второй способ.

§4Зачем нужен список

Построчный перебор из главы 8.9 экономнее, но список умеет то, чего перебор не может.

§5Аргумент sizehint

Необязательный аргумент ограничивает объём чтения — но работает не так, как можно подумать.

Обратите внимание: в строке тринадцать символов, а лимит был десять. Метод не обрезает строки — он только решает, читать ли следующую.

§6Как работает sizehint

  1. Метод читает очередную строку целиком.
  2. Складывает её длину с уже прочитанным.
  3. Если сумма достигла sizehint — останавливается.
  4. Иначе читает следующую строку.

Отсюда и название: это подсказка (hint), а не жёсткая граница. Даже readlines(1) вернёт одну целую строку — метод никогда не отдаёт обрезанные строки.

Этим sizehint отличается от size у read() и readline(): те обрезают ровно по счёту.

§7Пустой файл

Для пустого файла метод возвращает пустой список — не None и не ошибку.

Цикл по такому списку просто не выполнится ни разу — проверять отдельно обычно не требуется.

§8Позиция после чтения

readlines() дочитывает файл до конца, поэтому позиция оказывается в конце — со всеми последствиями из главы 8.8.

Впрочем, повторное чтение здесь и не нужно: полученный список можно перебирать сколько угодно раз — в этом и смысл.

§9Пара с writelines()

Теперь становится понятно, почему writelines() из главы 8.7 не добавляет переводы строк: два метода образуют пару.

Переводы строк уже внутри элементов — добавь их writelines() сам, копия получилась бы с двойными интервалами.

§10readlines() или перебор

Главный недостаток — память: список держит весь файл целиком, да ещё и с накладными расходами на сам список.

§11Три способа получить строки

Первые два одинаково расходуют память — оба читают файл целиком. Выбор между ними определяется только тем, нужны ли символы \n в элементах.

§13Проверьте себя

Что возвращает readlines()?

Список строк файла, каждая — вместе с завершающим переводом строки.

Как получить список без \n?

file.read().splitlines() или включение со strip() по результату readlines().

Обрежет ли readlines(10) длинную строку?

Нет. Метод дочитывает строку целиком и только потом решает, читать ли следующую. Это подсказка, а не жёсткая граница.

Почему writelines() не добавляет переводы строк?

Он парный к readlines(), который их сохраняет. Иначе при обратной записи переводов стало бы вдвое больше.

Когда readlines() предпочтительнее перебора?

Когда нужен именно список: доступ по индексу, длина, сортировка, сравнение соседних строк или повторный проход.

Что вернёт метод для пустого файла?

Пустой список []. Ни ошибки, ни None.

Итог главы

readlines() возвращает список всех строк файла вместе с переводами — и потому образует пару с writelines(), позволяя воспроизвести файл точь-в-точь. Список даёт то, чего не даёт построчный перебор: длину, индексы, сортировку и повторные проходы. Аргумент sizehint ограничивает объём, но строки не обрезает — это подсказка, а не лимит. Цена всего этого — весь файл в памяти, поэтому для больших файлов остаётся перебор.
