Замена, разбиение
и преобразование строк

replace() заменяет подстроки, split() превращает строку в список частей, splitlines() понимает границы строк, а upper(), swapcase() и zfill() создают новое представление текста. Это последняя группа строковых методов и самая используемая на практике.

«Хорошая обработка текста состоит из маленьких преобразований с понятным результатом.»

§1replace(): все вхождения

replace(old, new) возвращает строку, где каждое вхождение подстроки заменено на другую.

По умолчанию заменяются все вхождения — этим метод отличается от remove() у списков из главы 3.10, который убирал только первое. Если подстрока не найдена, возвращается копия исходной строки без ошибки.

§2Ограничение числа замен

Третий аргумент задаёт максимальное количество замен, считая слева.

Это нужно, когда одинаковые символы играют в строке разные роли: здесь первые два дефиса разделяют дату, а третий отделяет примечание.

§3Удаление через replace()

Если заменить подстроку на пустую строку, она просто исчезнет. Это стандартный способ удалить символы внутри строки — там, где strip() из главы 5.9 бессилен.

§4split(): строка в список

split(sep) разбивает строку по разделителю и возвращает список частей. Сам разделитель в результат не попадает.

Пустая строка в середине — не ошибка, а точное отражение данных: между двумя точками с запятой действительно ничего нет. Для таблиц это правильное поведение, потому что число полей сохраняется.

§5split() без аргумента

Без аргумента метод ведёт себя иначе: он делит по сериям любых пробельных символов и отбрасывает пустые части по краям.

Это готовый способ разбить текст на слова: не нужно ни очищать края, ни думать о двойных пробелах.

§6split() против split(" ")

Разница между вызовом без аргумента и с пробелом выглядит косметической, но поведение у них разное.

split()split(" ")

Практическое правило: разбиваете текст на слова — split() без аргумента; разбираете структурированную запись с фиксированными полями — явный разделитель.

§7Пустая строка

Та же разница проявляется на пустой строке, и это регулярно ломает обработку данных.

Длина результатов разная — 0 и 1. Цикл по первому не выполнится ни разу, по второму выполнится один раз с пустым значением. Если данные приходят из файла, где встречаются пустые строки, эту разницу нужно учитывать явно.

§8maxsplit

Второй аргумент ограничивает число разбиений. Всё, что осталось, попадает в последний элемент целиком.

Приём незаменим при разборе логов: уровень и дату нужно отделить, а текст сообщения — сохранить как есть, даже если в нём встретится разделитель.

§9rsplit()

rsplit() отсчитывает разбиения справа. Без maxsplit результат совпадает с split() — разница появляется только вместе с ограничением.

Логика та же, что у rfind() и rpartition() из глав 5.5 и 5.9: приставка r всегда означает «с конца».

§10splitlines() против split()

Для разбиения на строки есть отдельный метод, и он не равнозначен split() с переводом строки.

Файлы почти всегда заканчиваются переводом строки, поэтому split("\n") регулярно даёт «лишнюю пустую строку в конце». splitlines() этой проблемы лишён — он понимает, что последний перевод завершает строку, а не начинает новую.

Второе преимущество: \r\n — окончание строк в Windows — распознаётся как одна граница. С split("\n") символ \r остался бы в конце каждой части и портил бы сравнения.

§11keepends

Если окончания строк нужно сохранить, передают keepends=True.

Это нужно, когда текст разбирают, что-то в нём меняют и собирают обратно: с сохранёнными окончаниями достаточно склеить части через "".join(), и исходное форматирование не пострадает.

§12Практика: разбор записи

split() вместе с распаковкой из главы 6.6 разбирает строку данных в одну строку кода.

Распаковка требует точного числа полей

Если в записи окажется не три поля, а два или четыре, будет ValueError. Для данных из внешнего источника надёжнее сохранить результат в список и проверить его длину — либо задать maxsplit, чтобы число частей было предсказуемым.

И ещё одно: split(",") не понимает кавычек, поэтому значение вида "Москва, Россия" он разорвёт. Для настоящих CSV-файлов есть модуль csv — он разбирается в модуле 8.

§14zfill()

zfill(width) дополняет строку нулями слева до нужной длины. Название — от zero fill.

Метод специально умеет обращаться со знаком: он ставит нули после - или +, а не перед ним. Этим он отличается от rjust(5, "0") из главы 5.3, который сдвинул бы знак вправо и дал бы неверное 00-42.

Как и center(), метод не обрезает: если строка уже длиннее width, она возвращается целиком.

§16Проверьте себя

Сколько вхождений заменит replace(old, new)?

Все. Чтобы ограничить количество, передают третий аргумент.

Чем split() отличается от split(" ")?

split() делит по сериям любых пробельных символов и отбрасывает пустые края. split(" ") ищет каждый одиночный пробел, из-за чего двойной пробел даёт пустую часть.

Почему "".split() и "".split(",") дают разные результаты?

Первый возвращает пустой список, второй — список из одной пустой строки. Их длины 0 и 1, и цикл по ним поведёт себя по-разному.

Когда нужен rsplit()?

Когда число разбиений ограничено, а искать разделители нужно с конца — например, чтобы отделить расширение файла.

Почему для строк файла лучше splitlines()?

Он не создаёт лишний пустой элемент из завершающего перевода строки и распознаёт \r\n как одну границу.

Чем zfill(5) лучше rjust(5, "0") для чисел?

zfill() ставит нули после знака: -42 станет -0042, а не 00-42.

Итог главы

replace() заменяет все вхождения, если не ограничить их третьим аргументом, и заменой на пустую строку удаляет символы внутри текста. У split() две разные повадки: без аргумента он режет по сериям пробельных символов и годится для разбиения на слова, с явным разделителем — сохраняет пустые поля и годится для структурированных записей. Для строк текста нужен splitlines(): он не оставляет лишнего пустого элемента в конце и понимает окончания строк Windows. zfill() дополняет нулями, аккуратно обходясь со знаком числа.
