8.6

Запись в файл:
write()

Метод записывает строку в текущую позицию и не делает ничего сверх этого: не добавляет перевод строки, не преобразует числа, не спрашивает подтверждения. Два следствия — самые частые сюрпризы темы: всё слипается в одну строку, а режим "w" стирает файл при открытии.

§1Последовательная запись

Последовательный доступ из главы 8.4 означает, что данные пишутся подряд: каждая новая порция ложится в текущую позицию, а позиция сдвигается вперёд. Перескочить к произвольному месту нельзя — этим занимается seek() из главы 8.11.

Для записи файл открывают в подходящем режиме, и выбор режима здесь важнее, чем при чтении: ошибка стоит потерянных данных.

§2Режимы для записи

РежимЧто делаетСуществующее содержимое
"w"открывает для записиудаляется
"a"открывает для дозаписисохраняется, запись идёт в конец
"wb"двоичная записьудаляется
"w+"запись и чтениеудаляется

Во всех четырёх случаях файл будет создан, если его нет. Разница только в судьбе существующего содержимого.

§3Метод write()

write(string) записывает строку в текущую позицию файла.

Никаких добавлений: ни пробела, ни перевода строки, ни кавычек. Что передали — то и оказалось в файле.

§4Что возвращает write()

Метод возвращает количество записанных символов — в отличие от методов изменения коллекций из модуля 3, которые возвращали None.

Обратите внимание: символов, а не байтов. В UTF-8 эти шесть букв займут на диске двенадцать байтов — разница из главы 5.4. В двоичном режиме метод вернёт именно число байтов.

§5Перевод строки не добавляется

Самая частая неожиданность: два вызова подряд не создают двух строк.

Это отличает write() от print(), который перевод строки добавляет сам — параметр end из главы 1.4. Здесь такого умолчания нет.

§6Режим w стирает файл

Второе важное свойство, и оно разрушительное: содержимое удаляется в момент открытия, ещё до первого write().

При каждом запуске файл обнуляется

Программа, которая ведёт журнал в режиме "w", при каждом запуске теряет весь предыдущий журнал. Ошибка не проявляется на первом запуске — она проявляется на втором, когда терять уже есть что.

§7Режим a дописывает

Когда существующее содержимое нужно сохранить, берут режим "a" — от append.

ЗадачаРежим
создать отчёт заново"w"
вести журнал событий"a"
сохранить настройки"w"
копить измерения"a"

§8Запись нескольких строк

Чтобы записать список строк, write() вызывают в цикле, добавляя перевод строки.

Для этой задачи есть и специальный метод writelines() — ему посвящена глава 8.7. Забегая вперёд: перевод строки он тоже не добавляет.

§9Только строки

Аргумент должен быть строкой. Число метод не примет.

Это снова отличие от print(), который приводит к строке что угодно. Здесь преобразование нужно делать самому.

§10Запись чисел

Помните вывод главы 8.4: в текстовом файле лежат символы, а не числа. При чтении обратное преобразование делают через int() или float().

§11Двоичный режим

В режиме "wb" метод принимает не строку, а байты — тип bytes из главы 5.4.

Здесь видна разница из §4: символов было шесть, байтов записано двенадцать. Попытка передать обычную строку в двоичный файл даёт TypeError: a bytes-like object is required, not 'str'. Аргумент encoding в двоичном режиме не указывают — кодирование выполняется вручную.

§12Зачем нужен двоичный формат

ПричинаВ чём выигрыш
компактностьчисло занимает меньше места, чем его текстовая запись
скоростьне нужно кодировать и разбирать текст
точностьдробные числа сохраняются без округления при выводе
нетекстовые данныеизображения, звук, архивы текстом не выразить

Плата — нечитаемость: такой файл не открыть Блокнотом и не поправить руками. Поэтому настройки и журналы обычно хранят текстом, а данные большого объёма — в двоичном виде.

§13Режим w+

Плюс к режиму означает «и чтение, и запись через один объект».

Вызов seek(0) обязателен: после записи позиция стоит в конце файла, и чтение вернуло бы пустую строку. Работа с позицией разбирается в главе 8.11. Режим "w+", как и "w", стирает файл при открытии — для чтения существующего с возможностью правки берут "r+".

§15Проверьте себя

Когда режим "w" удаляет содержимое файла?

В момент открытия — ещё до первого вызова write(). Даже если запись не состоится, файл уже пуст.

Добавляет ли write() перевод строки?

Нет. В отличие от print(), символ \n нужно дописывать самому.

Что возвращает write()?

Количество записанных символов в текстовом режиме и количество байтов — в двоичном.

Почему file.write(42) — ошибка?

Метод принимает только строку и ничего не преобразует. Нужен str(42) или f-строка.

Чем "a" отличается от "w"?

"a" сохраняет существующее содержимое и пишет в конец, "w" очищает файл при открытии.

Зачем seek(0) в режиме "w+"?

После записи позиция стоит в конце файла, и чтение вернуло бы пустую строку. seek(0) возвращает её в начало.

Итог главы

write() записывает строку в текущую позицию и возвращает число записанных символов. Он не добавляет перевод строки и не преобразует числа — обе привычки достались от print() и здесь не работают. Режим определяет судьбу существующего содержимого: "w" стирает файл уже при открытии, "a" дописывает в конец. В двоичном режиме метод принимает bytes, и строку приходится кодировать вручную.
