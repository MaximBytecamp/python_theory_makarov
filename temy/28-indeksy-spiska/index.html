Перебор списка
по индексам

§1Зачем нужны индексы

Обычный цикл for number in numbers выдаёт значения элементов и ничего не сообщает об их позициях. Пока задача сводится к чтению — вывести, посчитать сумму, найти максимум — этого достаточно.

Но некоторые задачи формулируются именно через позицию: «заменить каждый элемент на удвоенный», «сравнить элемент со следующим», «поменять местами первый и последний». Для них нужна не копия значения, а сам номер ячейки.

Позиция ценна тем, что по ней можно вернуться к списку и не только прочитать элемент, но и записать в него новое значение.

§2Разбор конструкции

Пусть numbers = [10, 20, 30, 40]. Выражение len(numbers) даёт 4, а range(4) — индексы 0, 1, 2, 3.

Выражение читается изнутри наружу.

  1. len(numbers) вычисляется первым и даёт количество элементов — 4.
  2. range(4) превращает количество в набор позиций 0, 1, 2, 3.
  3. Цикл for перебирает этот набор и кладёт очередное число в переменную index.
Почему именно len(), а не 4

Число 4 пришлось бы исправлять вручную при каждом изменении списка. len(numbers) вычисляется при запуске и подходит любому списку, включая пустой: тогда range(0) пуст, и тело цикла не выполнится ни разу.

§3Индекс и элемент

index хранит позицию, а numbers[index] получает элемент на этой позиции. Это два разных значения, и путать их — самая частая ошибка в теме.

В левом столбце — номера позиций, в правом — то, что в этих позициях лежит. Совпадать они не обязаны и обычно не совпадают.

§5Изменение элемента

Главная строка всей главы выглядит так:

Слева и справа стоит одна и та же запись numbers[index], но работает она по-разному. Python вычисляет присваивание справа налево.

  1. Сначала полностью вычисляется правая часть. Запись numbers[index] справа означает «взять значение из ячейки»: при index = 0 получится 1.
  2. Полученное значение умножается на 2 — получается 2. Список в этот момент ещё не изменён.
  3. Затем срабатывает левая часть. Запись numbers[index] слева означает «положить значение в ячейку» — результат записывается в позицию 0 списка.

Иначе говоря, квадратные скобки слева от знака = адресуют ячейку, а справа — достают её содержимое. Именно поэтому старое значение успевает поучаствовать в вычислении нового.

§6Трассировка изменения

Чтобы увидеть механику целиком, полезно расписать все четыре повтора и состояние списка после каждого из них.

indexПрочитано справаВычисленоСписок после шага
011 * 2 = 2[2, 2, 3, 4]
122 * 2 = 4[2, 4, 3, 4]
233 * 2 = 6[2, 4, 6, 4]
344 * 2 = 8[2, 4, 6, 8]

Список меняется постепенно, по одной ячейке за повтор. Новый список не создаётся: всё это время numbers указывает на одну и ту же коллекцию, у которой обновляется содержимое.

Сокращённая запись

Строку можно записать короче: numbers[index] *= 2. Результат тот же, порядок действий тот же. Начинающим полезнее сначала освоить полную форму, чтобы видеть чтение и запись явно.

§7Почему обычный for не меняет список

Логично попробовать сделать то же самое без индексов. Такой код запускается, не выдаёт ошибок — и не работает.

Причина в том, что number — это отдельная переменная цикла, а не сама ячейка списка. На каждом повторе в неё копируется значение элемента.

numbers[0]→1
number→1

Строка number = number * 2 присваивает новое значение имени number. Связь между этим именем и позицией 0 при этом теряется: переменная начинает указывать на число 2, а ячейка списка по-прежнему хранит 1.

numbers[0]→1
number→2

На следующем повторе number просто перезаписывается значением следующего элемента, и вычисленная двойка теряется бесследно. Чтобы изменение попало в список, адресовать нужно ячейку — то есть писать numbers[index] = ....

Ошибки не будет — будет неверный результат

Это опасный случай: программа отрабатывает молча, вывод выглядит правдоподобно, и заметить проблему можно только по значениям. Если после цикла список «почему-то не изменился» — первым делом проверьте, присваиваете вы в переменную или в позицию списка.

§8Соседние элементы

Вторая причина использовать индексы: имея позицию, можно обратиться и к соседним — index - 1 и index + 1.

Диапазон здесь сокращён на единицу, и это не случайность. В списке из четырёх элементов последний индекс равен 3; для него выражение numbers[index + 1] потребовало бы несуществующий индекс 4. Поэтому цикл останавливают на предпоследней позиции.

Общее правило

Если внутри используется смещение index + k, диапазон нужно сократить так, чтобы последний индекс со смещением оставался допустимым: range(len(items) - k).

§9Задача на соседей

Приём с парами применяют там, где важна не сама величина, а изменение между соседними измерениями. Найдём максимальный скачок температуры между соседними днями.

indexПараjumpmax_jump после шага

Обычным перебором значений такую задачу не решить: на каждом шаге нужны сразу два элемента, а for value in temperatures выдаёт только один.

§10Обратный перебор

Индексы позволяют идти по списку с конца. Для этого range() задают с отрицательным шагом.

АргументЗначениеСмысл
startlen(letters) - 1 → 2последний допустимый индекс
stop-1граница не включается, поэтому 0 ещё обрабатывается
step-1движение к меньшим индексам

Если нужны только значения и не нужны позиции, короче написать for letter in reversed(letters). Индексная форма выигрывает тогда, когда с конца требуется ещё и что-то изменять.

§11Границы списка и IndexError

Допустимые индексы списка идут от 0 до len(items) - 1. Обращение к позиции за этой границей останавливает программу.

Последняя строка называет тип ошибки, а стрелки под кодом показывают, какое именно обращение оказалось неверным. В списке из трёх элементов позиции — 0, 1 и 2; индекс 3 лежит уже за концом.

Отсчитывать с конца можно отрицательными индексами: -1 — последний элемент, -2 — предпоследний.

Обе записи дают последний элемент. Форма prices[-1] короче и читается лучше, а len(prices) - 1 нужна тогда, когда позиция участвует в вычислениях.

range(len(items) + 1) — источник IndexError

Соблазн «дотянуться до последнего элемента» прибавлением единицы приводит к обратному: range(len(items)) уже включает последний индекс, а + 1 добавляет несуществующий.

§12enumerate(): индекс и значение

Если позиция нужна только для вывода или проверки, а не для записи, удобнее enumerate(). Он выдаёт сразу пару: индекс и элемент.

Для нумерованного списка на экране удобен аргумент start: он меняет только выводимые номера, но не позиции в списке.

Подробнее enumerate() разбирается в главе 3.7. Важно помнить, что переменная значения в нём ведёт себя так же, как в обычном цикле: присваивание в неё список не изменит — для этого всё равно нужна запись colors[index] = ....

§13Когда нужны индексы

  • изменить элементы исходного списка;
  • обратиться к предыдущему или следующему элементу;
  • сравнить позиции в алгоритме сортировки или поиска;
  • обработать только определённый диапазон позиций;
  • пройти список в обратном порядке и что-то в нём поменять;
  • работать одновременно с двумя списками одинаковой длины.

Если ни одна из этих причин не подходит, обычный перебор элементов читается проще и ошибиться в нём почти невозможно.

§15Проверьте себя

Что создаёт range(len(numbers))?

Допустимые индексы списка от нуля до len(numbers) - 1.

Почему в строке numbers[index] = numbers[index] * 2 одна и та же запись означает разное?

Справа от знака = скобки читают значение из ячейки, слева — указывают ячейку для записи. Сначала вычисляется правая часть, затем результат кладётся в позицию.

Почему for number in numbers: number *= 2 не меняет список?

number — отдельная переменная, в которую скопировано значение. Присваивание перепривязывает имя, а ячейка списка остаётся прежней.

Зачем сокращать диапазон при обращении к index + 1?

Чтобы для последней итерации следующий индекс продолжал существовать.

Как перебрать список от последнего элемента к первому?

for index in range(len(items) - 1, -1, -1). Граница -1 не включается, поэтому нулевая позиция обрабатывается.

Когда лучше обычный for number in numbers?

Когда нужен только сам элемент и позиция не используется.

Итог главы

len() даёт размер, range() превращает его в допустимые индексы, а items[index] получает или изменяет элемент. Ключевое отличие индексного перебора в том, что он адресует ячейку списка, а не копию значения, — поэтому только через него список можно менять на месте. Использовать его стоит тогда, когда задача действительно зависит от позиции.
