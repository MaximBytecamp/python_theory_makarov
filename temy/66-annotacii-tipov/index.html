6.11

Аннотации типов

Аннотация указывает, какой тип ожидается у параметра, возвращаемого значения или переменной. На выполнение программы она не влияет: это документация, которую читают человек и анализатор кода.

§1Зачем нужны аннотации

По заголовку функции без аннотаций не видно, с чем она работает. Строка def add(a, b) одинаково подходит и для чисел, и для строк, и для списков.

Аннотация типа — это пометка о том, какой тип значения ожидается. Она решает три задачи: документирует код, позволяет редактору подсказывать методы и даёт статическим анализаторам вроде mypy находить несоответствия до запуска программы.

§2Синтаксис

Тип параметра пишут после имени через двоеточие, а тип результата — после стрелки -> перед двоеточием заголовка.

Использовать можно любые встроенные типы: int, float, str, bool, list, dict и другие. Имя типа пишется без кавычек и без скобок.

§3Аннотация не проверяет тип

Это главное, что нужно понять про аннотации: Python их не исполняет. Функция с аннотацией int спокойно примет строки.

«Ошибка» здесь — это предупреждение

Редактор или mypy подчеркнут такой вызов, но программа от этого хуже работать не станет и не упадёт. Аннотация — обещание разработчика, а не проверка во время выполнения. Если проверка типа действительно нужна, её пишут явно: if not isinstance(a, int): ...

Обратная сторона тоже верна: несоответствие типов может привести к настоящей ошибке позже — там, где значение не поддержит нужную операцию. Аннотации помогают заметить это заранее.

§4Возвращаемое значение и None

Если функция ничего не возвращает, её результат — None, и это записывают явно.

Запись -> None означает «возвращать нечего». Она отличает такую функцию от той, где программист просто забыл указать тип результата.

§5Коллекции в аннотациях

Для коллекции полезно указать не только сам тип, но и тип элементов. Это делают квадратными скобками.

АннотацияЧто означает
list[int]список целых чисел
tuple[int, str]кортеж из двух элементов: число и строка
dict[str, int]словарь со строковыми ключами и целыми значениями
set[str]множество строк
Так было не всегда

Встроенные типы принимают квадратные скобки начиная с Python 3.9. До этого требовался модуль typing: from typing import List и затем List[int]. В коде для старых версий такая запись ещё встречается.

§6Несколько типов через |

Когда допустимо несколько типов, их перечисляют через вертикальную черту.

Здесь аннотация и настоящая проверка работают вместе: int | str сообщает читателю о замысле, а isinstance() действительно разделяет случаи во время выполнения.

§7Значение может отсутствовать

Частный, но очень частый случай — функция возвращает результат либо None, если ничего не нашла.

Такая аннотация — предупреждение вызывающему коду: результат нужно проверить перед использованием. В старых версиях то же самое записывали как Optional[str] из модуля typing.

§8Аннотации переменных

Аннотировать можно не только функции. Переменной тип указывают так же — через двоеточие после имени.

То же работает внутри функции для локальных переменных: count: int = 0. Значение можно и не присваивать — запись total: int объявляет только тип, но саму переменную не создаёт, и обращение к ней вызовет NameError.

§9Атрибут __annotations__

Аннотации не исчезают при запуске: Python складывает их в словарь __annotations__, где ключи — имена, а значения — типы.

Тип возвращаемого значения лежит под специальным ключом 'return'. У классов есть свой такой словарь — по аннотациям атрибутов.

Где объявленыКак получить
параметры и результат функцииfunction.__annotations__
атрибуты классаClassName.__annotations__
переменные модуля__annotations__ на уровне модуля

В повседневном коде этот словарь почти не нужен. Он важен библиотекам, которые строят поведение по аннотациям, — так работают, например, валидация данных в Pydantic и внедрение зависимостей в FastAPI.

§10Где аннотации не нужны

Аннотации — инструмент, а не обязанность. Они окупаются там, где код читают другие или где типы неочевидны.

СитуацияСтоит ли аннотировать
функция в общем модуле проектада, это её документация
функция возвращает разные типыда, обязательно — иначе неясно, что ожидать
короткий учебный скриптне обязательно
x: int = 10 для очевидного литералалишний шум, тип и так виден

Аннотация, которая не соответствует действительности, хуже её отсутствия: она вводит в заблуждение. Если тип изменился — исправьте аннотацию.

§12Проверьте себя

Остановит ли аннотация a: int передачу строки?

Нет. Аннотации не проверяются во время выполнения — программа отработает как обычно, а несоответствие подчеркнёт только анализатор кода.

Что означает -> None?

Функция ничего не возвращает: её результат — None.

Как записать «строка или ничего»?

str | None начиная с Python 3.10; раньше — Optional[str] из модуля typing.

Под каким ключом лежит тип результата в __annotations__?

Под ключом 'return'.

Нужен ли typing для list[int]?

Начиная с Python 3.9 — нет, встроенные типы принимают квадратные скобки сами.

Итог главы

Аннотации описывают ожидаемые типы параметров, результата и переменных. Они не влияют на выполнение: программа с «неправильным» типом отработает как обычно. Ценность аннотаций в другом — они документируют замысел, помогают редактору и позволяют статическому анализатору находить несоответствия до запуска.
