§1Три формулировки условий

Условия в задачах формулируют словами, и почти всегда встречается одна из трёх конструкций. Умение узнавать их и есть навык, ради которого написана глава.

ФормулировкаСмыслЧем записывается
Каждое — «все три числа кратны трём»истинны все условия без исключенияand
Хотя бы одно — «среди чисел есть отрицательное»истинно одно или большеor
Только одно — «одно число чётное, другое нет»истинно ровно одно, остальные ложныand и or вместе

Первые две записываются напрямую, третья требует сборки. Разберём каждую на конкретной задаче.

§2Кирпичик: проверка делимости

Почти во всех примерах этой главы встречается одна и та же проверка, поэтому разберём её отдельно. Выражение A % 3 == 0 проверяет, делится ли A на три без остатка.

Читается оно справа налево от оператора: A % 3 — остаток от деления (глава 1.8), == 0 — сравнение этого остатка с нулём. Если остатка нет, значит число разделилось нацело, и всё выражение даёт True.

Каждая такая строка — готовое логическое значение. Составное условие всегда собирается из подобных кирпичиков, и разбирать чужое условие тоже стоит начиная с них: сперва понять, что проверяет каждая часть, и лишь потом — как они связаны.

§3Каждое — оператор and

Задача: проверить, что числа A, B и C кратны трём. Слово «и» между требованиями означает and.

Операторов and может быть сколько угодно — выражение остаётся истинным, только если истинны все части сразу. Достаточно одному числу не разделиться на три, чтобы результат стал False.

Скобки вокруг каждой проверки не обязательны: сравнение == и без того выполняется раньше and. Но со скобками структура выражения видна сразу — три отдельных проверки, соединённые «и», — поэтому в длинных условиях их ставят.

На полях: and останавливается досрочно

Python вычисляет составное условие слева направо и прекращает, как только ответ определён. В цепочке and первое же ложное условие делает ложным всё выражение, и остальные проверки просто не выполняются. Это не оптимизация «под капотом», а поведение, на которое можно опираться: слева ставят самую дешёвую или самую отсекающую проверку.

§4Хотя бы одно — оператор or

Задача: проверить, есть ли среди чисел A, B, C отрицательное. Здесь достаточно одного попадания, значит нужен or.

Результат истинный, потому что A меньше нуля. Что B и C положительны, роли не играет: or требует истинности хотя бы одной части. Ложным всё выражение станет, только если ни одна проверка не сработает.

§5Только одно — комбинация

Самая интересная из трёх формулировок. Задача: проверить, что из двух чисел одно чётное, а другое нечётное — то есть ровно одно чётное.

Одним оператором это не записать. Разложим условие на два случая, каждый из которых нас устраивает:

  1. A чётное и B нечётное — записывается как A % 2 == 0 and B % 2 != 0;
  2. A нечётное и B чётное — записывается как A % 2 != 0 and B % 2 == 0;
  3. нас устраивает любой из этих случаев — значит, соединяем их через or.

Четвёрка чётная, семёрка нечётная — сработала первая половина условия, и этого достаточно. Если бы оба числа оказались чётными, ложными стали бы обе половины, и результат был бы False. Это и отличает «ровно одно» от «хотя бы одно»: случай «оба сразу» здесь запрещён.

Скобки в этой записи уже обязательны по смыслу — они показывают, что or соединяет два целых случая, а не отдельные проверки. Формально приоритет and выше и без них, но полагаться на это в выражении такой длины не стоит: скобки пишутся для читателя.

§6Ни одного и не все

Ещё две формулировки встречаются постоянно, и обе получаются из уже разобранных отрицанием.

ФормулировкаКак записатьЧерез что получается
ни одно из чисел не отрицательноnot (A < 0 or B < 0)отрицание «хотя бы одного»
то же самое напрямуюA >= 0 and B >= 0каждое неотрицательно
не все числа кратны трёмnot (A % 3 == 0 and B % 3 == 0)отрицание «каждого»

Первые две строки таблицы описывают одно и то же условие разными словами — и это не совпадение. Отрицание «хотя бы одного» всегда равно «каждое наоборот», а отрицание «каждого» — «хотя бы одно наоборот». Правило известно как законы де Моргана, но заучивать формулировку не нужно: достаточно помнить, что not вокруг скобок меняет и сами проверки, и and с or местами.

Из двух эквивалентных записей выбирайте ту, которая ближе к формулировке задачи. Если в условии сказано «оба числа неотрицательны» — пишите A >= 0 and B >= 0. Если «нет ни одного отрицательного» — not (A < 0 or B < 0) честнее передаёт мысль.

§7Как собирать длинные условия

Когда проверок становится больше трёх, выражение перестаёт читаться. Порядок работы, который выручает:

  1. Выпишите словами каждое требование задачи отдельной строкой.
  2. Переведите каждое в простую проверку — тот самый кирпичик из §2.
  3. Определите связку: «и» между всеми — and, «или» — or, «ровно одно» — комбинация.
  4. Дайте промежуточным проверкам имена, если их больше трёх.

Строка A or B or C < 0 выглядит как «A или B или C меньше нуля» — ровно так, как задача звучит по-русски. Но язык читает её иначе: сначала A как логическое значение, затем B, и только потом настоящую проверку C < 0. А любое ненулевое число истинно, помните §3 прошлой главы. Программа не упадёт и выдаст правдоподобный ответ — тем эта ошибка и опасна. Каждой проверке нужна своя полная запись.

§9Проверьте себя

Как записать условие «все три числа положительны»?

(A > 0) and (B > 0) and (C > 0). Формулировка «все» переводится цепочкой and: достаточно одному числу оказаться неположительным, и результат станет False.

Чем условие «хотя бы одно из двух чётное» отличается от «ровно одно из двух чётное»?

Случаем, когда чётны оба. «Хотя бы одно» — это A % 2 == 0 or B % 2 == 0, и при двух чётных числах оно истинно. «Ровно одно» в этом случае должно давать False, поэтому его собирают из двух взаимоисключающих вариантов через and и or.

Что проверяет выражение A % 5 == 0 and A % 3 == 0?

Что число A делится и на пять, и на три одновременно, то есть кратно пятнадцати. Обе проверки должны быть истинными — этого требует and.

Почему not A < 0 or B < 0 и not (A < 0 or B < 0) — разные условия?

У not приоритет выше, чем у or, поэтому в первой записи отрицание относится только к A < 0: получается «A неотрицательно или B отрицательно». Во второй скобки заставляют сначала вычислить всё условие целиком, и смысл становится «ни одно из чисел не отрицательно». Скобки здесь не украшение, а часть условия.

Задача для практики: пользователь вводит три числа. Проверьте, что ровно одно из них равно нулю.

Формулировка «ровно одно» разворачивается в три случая — по одному на каждое число, — и в каждом остальные должны быть ненулевыми:

  • (A == 0 and B != 0 and C != 0) or
  • (A != 0 and B == 0 and C != 0) or
  • (A != 0 and B != 0 and C == 0)

Есть и короткий путь, опирающийся на то, что True равно единице: (A == 0) + (B == 0) + (C == 0) == 1 — сумма истинных проверок должна равняться одному. Второй вариант короче, но требует от читателя знания про подкласс int; выбирайте по тому, кто будет читать код.

Итог главы

Словесная формулировка задачи переводится в выражение почти механически: «каждое» — это цепочка and, «хотя бы одно» — цепочка or, «только одно» — набор взаимоисключающих случаев, соединённых or. Собирается любое условие из простых проверок вроде A % 2 == 0, и разбирать чужое условие тоже стоит начиная с них. Длинные выражения раскладывайте на именованные части — читателю кода это важнее, чем экономия строк. Готовые условия мы теперь передадим оператору if, и программа наконец начнёт выбирать путь.
