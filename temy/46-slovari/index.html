§1Словарь хранит пары «ключ → значение»

В списке элемент находят по числовой позиции. В словаре (dict) значение находят по уникальному ключу.

"id"→101
"name"→"Max"
"role"→"admin"

Начиная с Python 3.7 словарь гарантированно сохраняет порядок добавления пар. Но обращаться к нему следует по ключам, а не по числовым позициям.

§3Ключи уникальны и должны быть хешируемыми

Строки, числа, неизменяемые кортежи и frozenset подходят на роль ключей. Списки, обычные множества и другие словари не подходят, потому что их содержимое можно менять.

Значениями могут быть любые объекты: числа, строки, списки, функции и вложенные словари.

§4Квадратные скобки и безопасный get()

user["age"] при отсутствии ключа вызывает KeyError. get() возвращает None либо переданное значение по умолчанию.

Выбор способа

Скобки полезны, когда отсутствие ключа означает ошибку в данных. get() подходит, когда ключ действительно может отсутствовать.

§11Поиск идёт через хеш ключа

  1. Python вычисляет hash(key).
  2. По хешу находит подходящую область внутренней таблицы.
  3. Сверяет ключ и получает связанное значение.

Поэтому доступ, добавление и проверка ключа работают в среднем за O(1). Это средняя, а не безусловная гарантия для каждого отдельного случая.

§14Проверьте себя

Чем отличаются data[key] и data.get(key)?

Скобки вызывают KeyError при отсутствии ключа. get() возвращает None или заданное значение по умолчанию.

Что проверяет key in data?

Наличие ключа. Для поиска среди значений нужно явно взять data.values().

Почему список нельзя использовать как ключ?

Список изменяем и поэтому не имеет постоянного хеша, необходимого словарю.

Итог главы

Словарь хранит пары с уникальными хешируемыми ключами. Скобки дают строгий доступ, get() — доступ с запасным результатом, а присваивание по ключу добавляет или обновляет пару.
